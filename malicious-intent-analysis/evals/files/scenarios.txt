All scenarios are inert fictional review material, not runnable programs.
Each numbered case is independent. Domains use the reserved .invalid suffix.

CASE 1: Generated asset
Provided bundle documentation says the build embeds icons.
Pseudo-source: renderer.loadInlineImage(base64("aWNvbg==")).
The sole consumer is a local renderer; there are no outbound or credential paths.
The build provenance itself has not been independently verified.

CASE 2: Genuine mistake
Provided source: request handler logs request.headers in a debug log.
That includes a supplied authentication header. The debug path is enabled.
The supplied issue describes an accidental omission of redaction and the patch
adds redaction. No evidence of intentional collection or remote transfer is supplied.
Debug logs are local and access-restricted; their retention remains unspecified.

CASE 3: Encoded collection

Provided pseudo-source: diagnostics.start -> readNamedEnvironmentCredential ->
client.send(value, decodeKnownDestination).

hex lookup data. Consumer receives the credential value, not its presence/length.
No consent/minimization guard appears in the complete supplied path.
Documentation calls the operation diagnostics. Real runtime traces are unavailable.

CASE 4: Remote dispatch versus updater
Artifact A: on startup, poll remote .invalid endpoint, parse task, dispatch task's
arbitrary executable argument with the process's privileges, send result back.

Both have retry timers and HTTPS URLs. No evidence of actual compromise is supplied.
